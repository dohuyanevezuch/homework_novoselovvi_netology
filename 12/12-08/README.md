### Задание 2

#### Текст задания

1. С помощью официальной документации приведите пример команды резервирования данных и восстановления БД (pgdump/pgrestore).

2. Возможно ли автоматизировать этот процесс? Если да, то как?

Приведите ответ в свободной форме.

#### Выполнение задания

1. 
Создание дампа данных:

```bash
pg_dump -U root -h 127.0.0.1 -p 1234 -F c test_database -f dump_db
```

Восстановление дампа:

```bash
createdb -U root test_database2
pg_restore -U root -h 127.0.0.1 -p 1234 -d test_database2 dump_db
```

2. Да, можно, самы простой вариант это добавить правило в cron с командой создания дампа, а имя дампа дать на автоматику, например:

```bash
0 0 * * * pg_dump -U root -h 127.0.0.1 -p 1234 -F c targer_db -f /backup/targer_db_$(date +\%Y-\%m-\%d)
```

### Задание 3

#### Текст задания

3.1. С помощью официальной документации приведите пример команды инкрементного резервного копирования базы данных MySQL.

3.1.* В каких случаях использование реплики будет давать преимущество по сравнению с обычным резервным копированием?

Приведите ответ в свободной форме.

#### Выполнение задания

**3.1.** 

Включить бинарные логи в `/etc/mysql/mysql.conf.d/mysqld.cnf`, для этого требуется добавить:

```ini
server-id = 1
log-bin = mysql-bin
binlog_format = ROW
expire_logs_days = 7
```

Далее перезагрузить mysql

После требуется выполнить полный бекап, например:

```bash
mysqlbackup --defaults-file=/etc/mysql/mysql.conf.d/mysqld.cnf --backup-dir=/backups/full --with-timestamp --compress backup-and-apply-log
```

После полного бекапа можно выполнять команду для инкрементного бекапа

```bash
mysqlbackup --defaults-file=/etc/mysql/mysql.conf.d/mysqld.cnf --incremental --incremental-base=history:last_backup --backup-dir=/backups/incremental__$(date +%Y%m%d_%H%M%S) backup
```

**3.2.**

Это завист от направления применения. Если требуется отказоустойчивость, то реплика, которая перехватит управление почти мгновенно, после подения master будет выйгрешнее. Если речь идет об разгрузке мастера от запростов чтения - тоже (Если несколько мастеров то и записи). Если речь об увеличении доступности (Рекплики могут быть раскиданы по всему миру), то вариант с репликой тоже будет выйгрывать.

Вообще это совершенно разные технологии и разные подходы, реплика не спасает об ОШИБОК, она спасает от части аварий, если специалист случайно удалит ту или иную таблицу\базу и тд, то реплика просто не спасет, по этому лучше иметь и реплики и бекапы, как полные так и, например, инкрементные
